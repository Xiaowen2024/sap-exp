# Stack Bowls 轨迹复刻评估 SOP v1

本 SOP 采用用户提供的 Evaluation Metrics。固定初始场景，回放同一条机器人／夹爪运动，评价碗的运动、接触行为和最终结果。机器人轨迹是输入。官方 policy reward 门槛不参与复刻质量评分。

## 0. 执行模式和证据冻结

优先使用 `existing-only`：读取已经完成的场景、原生状态轨迹、健康记录及参考视频，不启动模拟。没有的数据记为 `null / not_evaluated`，不能记为零误差、零断触或通过。只有明确授权补测时才添加原生逐步遥测。

记录每个输入文件的 SHA-256、源数据 revision、episode、引擎与碰撞后端版本、初始场景、几何、质量／惯量、摩擦、机器人／夹爪驱动和时间基准。对照使用相同场景和输入；改过夹爪模型的旧 r2 不混入当前 r3 主比较。

本次主比较：既有 MuJoCo 4.0.0 CPU articulated r3 和 SAP Internal `2325082` + Newton Convex articulated r3，episode_0000000，R=1。没有进行多 episode 的成功率估计。

## 1. 参考视频可观测性审查

先只看参考，不看模拟结果来拟合参考。检查头部、左右腕部视角的清晰度、遮挡、相机标定、物体身份及时间同步。保存带帧号的可观测性图。

- 能可靠恢复时：输出逐物体、逐时间的中心、碗轴线、有效性、使用视角、方法和位置／角度不确定度。
- 仅能看出二维轮廓时：二维投影残差只能作为辅助，不能冒充三维位置 RMSE。
- 轴对称且无可识别纹理时：不评价绕碗轴的旋转；比较轴线夹角，不把相对世界竖直方向的倾角当成参考姿态误差。
- 遮挡帧不插值成可靠参考，不依据“应当正确嵌套”等物理假设补出位姿。参考覆盖率分母使用真实录制帧 × 物体数；各视角使用情况另报。
- 明确区分不可见、估计失败和尚未做位姿估计。可见不等于已有可靠三维位姿。

## 2. Physical Fidelity

Object-trajectory error：在有可靠 estimated reference 的相同时间点，计算每个碗中心三维位置 RMSE，以及碗轴线夹角误差。保持原始时间对齐。DTW 如使用仅为辅助，不能代替主 RMSE。

Final-pose error：在统一的释放后静止窗口中，联合多帧／多视角估计参考中心和轴线，并与相同时窗的模拟比较。报告窗口内波动、各物体参考覆盖率和估计不确定度。不得将追加模拟尾段中的“官方最后一帧静止展示”当作真实参考观测。

两项都报告有效帧／物体覆盖率、参考方法与不确定度。两引擎误差之差小于参考不确定度时，不判定优劣。两个引擎彼此的差值只描述引擎分歧，不是对参考的误差。

## 3. Simulation Consistency

Geometric validity：用共同几何观察器，按物体对记录离散采样最大穿透、发生时间、采样间隔、覆盖范围，并检查碗壁／碗底穿越。结合接触处局部壁厚和几何近似误差解释严重程度。顶点采样内部深度只报为穿透下界，不能称为精确最大穿透；只有末帧时，只报末态，不冒充全程最大值。不同引擎原生接触间隙的峰值单独保留，不能直接当作同一独立几何指标比较。

Contact continuity：仅在有按物体对、按时间记录时，统计预先声明的持续支撑／抓持阶段的 duty、最长断触时长与反复脱离—碰撞。区分候选接触、承载接触和几何近接触。说明接触力阈值及敏感性；结合间隙和运动解释，正常接触切换不直接判错。总接触点数、整段最大接触点数不能代替 continuity。

Post-release settling：统一时窗内，逐碗报告 COM 线速度 RMS、世界角速度 RMS；同时报告速度峰值、COM 净漂移、路径长度和倾角波动以解释抖动／漂移。RMS 定义为 `sqrt(integral(||velocity||² dt) / window_duration)`，使用原始采样的梯形积分。稳定不等于最终位姿正确。

本次共同主窗口为 `[9.06, 9.56] s`：参考视频最后 0.5 s，两手在视频中已经退出碗附近。使用 10 ms 状态采样、每碗 51 个样本。追加模拟尾段 `[10.06, 10.56] s` 只作补充，不能拿不同窗口分别给两个引擎选更好的数值。

## 4. Task Outcome

逐 episode 检查所有碗是否正确嵌套、夹爪完全释放后是否在规定观察窗口保持堆叠。结合多视角和几何记录复核，不能用“倾角超过 10°”替代嵌套判断。

- 参考与模拟分别记录 observed outcome，并注明观察窗口和可见性。
- 有效成功还需排除明显穿透或夹爪持续托举。缺少排除证据时，标为 `valid_success=null / validity_pending`，不强行输出通过或失败。
- 在结果可确定时报告 outcome agreement、false success、false failure。单 episode 为二元结果，多 episode 才给比例；无法判定的个案单独列出，不混进分母。
- 如果参考成功，false success 在该参考标签下不适用；未知的模拟有效结果不能当作 false failure。
