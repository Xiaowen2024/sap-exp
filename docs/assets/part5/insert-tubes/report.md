# RoboDojo 插试管（insert_tubes）回放：5 轮迭代结果

日期 2026-11-17。官方自动生成示范 `insert_tubes/arx_x5/episode_0000000`（数据集版本 1127bda），回放双臂夹爪轨迹，物体自由。引擎：MuJoCo 4.0（CPU）、SAP 旧版（`sap-fix-gamma`，legacy 凸体碰撞）、SAP 新版（2325082，`SAP_WARP_CONVEX_BACKEND=newton`）。IPC 本次未跑。

## 结论

| 引擎 | 5 轮插入数（it1…it5） | 最好一轮 | 最好结果 | 主要问题 |
|---|---|---|---|---|
| MuJoCo 4.0 | 0, 2, 2, 1, 2 | **it2**：椭圆摩擦锥、`impratio=10`、`solref=[0.004,1]` | **2/3，官方 40 分**：tube1、tube2 插到底（深度 54 mm，倾斜 1.0–1.4°） | tube0 在夹爪碰到之前就在桌面上自己滚走（0.36–0.65 m） |
| SAP 旧版 | 0, 0, 0, 0, 0 | 无成功轮；最接近的是 it5 | 0/3 | 卡在孔口：锥形管尖进孔，管身架在孔沿，松手后倒下。it5 有一支管直立穿过孔口，但随后穿透架子底板和桌面（漏碰撞），不能算成功 |
| SAP 新版 | 0, 0, 0, 0, 0 | 无成功轮 | 0/3 | 同样卡孔口，5 轮里没有一支管通过孔口 |

一句话：这一任务上 MuJoCo 4.0 调到第 2 轮就有 2/3 的潜力；SAP 新旧两版 5 轮都插不进，失败点一致，都是孔口卡滞。这正是任务设计时预期的"反向检验"：SAP 的接触更稳，但管子在手里无法横向让位、自动对中，在 1 mm 径向间隙下进不去。

## 各轮记录（每轮的改动都只依据上一轮的失败）

结构化记录在 `tuning_log.json`，参数文件在 `params/`。

**MuJoCo 4.0**
1. 默认参数，0/3。tube0 抓取前在桌面上滚走；tube1/2 在手里滑移 20–58 mm、转 11–39°，最后倾斜超限。
2. `cone=elliptic`、`impratio=10`、`solref=[0.004,1]`，**2/3**。手内滑移降到约 6 mm；进孔时横向偏差约 8 mm，管子在手里滑动后自动对中到 ≈1 mm，松手后滑到底。
3. 加 `multiccd`，结果与 it2 逐位相同。原因是 MuJoCo 4.0 默认已开启多点接触（它现在是关闭类开关），这一轮实际没有改变任何东西，照实计入次数。
4. 加 `noslip_iterations=10`，1/3，反而更差：tube2 穿过桌面掉落，tube1 插入但倾斜 12.7°。
5. 回到 it2，`impratio=100`，2/3，与 it2 相同。

**SAP 旧版 / 新版**（两版每轮用同一组参数，因为它们暴露的问题相同）
1. 默认参数，0/3。抓取和搬运正常（抬升约 11 cm），但手指压进管子约 7 mm（原生 pair ke 只有 1250 N/m），手内滑移 4–11 mm。下降时管尖卡在孔口（z≈0.809，即架顶以下 16 mm，正好是锥尖长度），松手后倒下。
2. `pair_ke=5e4`，0/3。穿透降到 0.4–0.7 mm，但仍然卡孔口，横向偏差停在 4–12 mm，没有自动对中。
3. 再加 `contact_stiction_tolerance=1e-3`，0/3，几乎不变。
4. `contact_stiction_tolerance=1e-2`，0/3，仍然不变。说明卡滞不是摩擦正则化（"过黏"）造成的。
5. `pair_ke=5e4`，检测距离 `gap` 从原生 0.1 m 降到 2 mm。原生 0.1 m 时约有 2000 个预测接触，包括所有孔周围的碎块。结果 0/3：
   - 旧版：tube1 直立通过孔口，但随后穿透底板和桌面（管尖 z=0.755），属于漏碰撞；左臂驱动检查失败（转角误差 9°）。
   - 新版：仍然全部卡孔口后倒下。

未解释的部分：SAP 在孔口不能横向对中的具体机制。已排除摩擦正则化；检测距离会影响结果，但缩小后会漏碰撞。

## 共享几何与偏差

- **试管**：官方碰撞网格切成两块精确凸体，管身 r=14.0–14.6 mm、盖子 r=17.5 mm；质量 0.06 kg。不用单个凸包，因为单个凸包会撑到 15.7 mm，大于孔径。
- **架子**：静态（官方是 Geometry 对象）。
  - 顶板厚 4 mm，孔是直孔 r=15 mm；已核对官方网格，没有倒角。
  - 孔由 16 个凸扇区围成，扇区内弦与孔圆相切，所以孔只会变大、不会变小，最多大 0.29 mm。
  - 另有 4 根立柱和实心底板（顶面 z=−24 mm）。
- **夹爪**：沿用 Codex 叠碗 r3 的 X5 关节模型，没有改动（官方手指凸包、滑动关节、PD 2300/100、上限 100 N）。手臂由自由浮动的夹爪基座伺服代替。
- **摩擦**：所有接触统一 μ=0.225，即官方试管 0.45 与架子 0（未设置）的 PhysX 平均值。这对插孔侧壁是忠实的，对手指抓取和桌面偏宽松。
- dt=1 ms，时长 12.72 s 回放加 2 s 静置，试管初始抬高 0.2 mm。

## 已知问题与核查

- **我们自己的 bug，已修复**：第一版试管切分阈值错误，管身只剩 16 mm，导致三个引擎第一次运行无效。该结果保留在 `runs/invalid_split_bug/`，不计入 5 轮。
- **MuJoCo 桌面滚动的单独测试**（`roll_test.py`，只有桌面和一支管，没有夹爪）：
  - 三支管在 it2 参数下 2 s 都滚动 25–30 mm，与初始滚转角（0/3/7°）基本无关；
  - 只有默认参数加 7° 滚转这一组合能停住；
  - 同一初始位姿在 SAP 中只移动 4.6 mm 就停了。
  - 因此判为 MuJoCo 软接触行为，而不是 tube0 初始位姿的问题。
- 本次只回放了单个示范、单次运行，参数是在同一回放上调出来的。结果代表"调出来能达到的最好表现"，不代表泛化能力。

## 卡孔口的接触诊断（2026-11-17 追加）

做法：用各引擎目前最好的参数（MuJoCo it2；SAP 新旧两版 it2，`pair_ke=5e4`）重放同一条轨迹，只在 tube1 下降到孔口的 6.8–7.5 s 内，每 30 ms（下表的间隔）记录管子的每个接触点的位置、法向、间距和求解器给出的力。重放与正式运行一致：t=7.1 s 时管子位置差 0.00 / 0.09 / 0.05 mm。数据和分析在 `contact_probe/`（`probe/analysis.txt`）。

| 引擎 | 管尖碰到孔沿时的偏心 | 孔沿接触法向（竖直分量 / 指向孔心分量） | 孔沿对管子的力 | 之后 |
|---|---|---|---|---|
| MuJoCo | 8.6 mm | 0.53 / +0.85（沿锥面倾斜） | 2.3 N 指向孔心，竖直 2.3 N | 手指摩擦饱和（T/μN=1.00），管子在手里横滑，30 ms 内对中到 0.6 mm，滑到底 |
| SAP 旧版 | 7.5 mm | 1.00 / +0.01～0.06（竖直） | 竖直 10–13 N，指向孔心 −0.35～+0.9 N | 手指摩擦同样饱和，但管子是被往上顶、在手里竖直滑，偏心一直停在约 6 mm；松手后偏心立在孔沿上，0.3 s 内倒下 |
| SAP 新版 | 4.8 mm | 0.99–1.00 / −0.03～+0.04（竖直） | 竖直 4.7–13 N，指向孔心约 0 | 同旧版，偏心停在约 4.5 mm，之后倒下 |

结论：
- 两个引擎的手指摩擦都达到上限，所以失败不是摩擦或耗散过大造成的。
- 差别只在孔沿接触的法向：真实几何是孔沿的棱边压在管子的锥面上，法向应沿锥面倾斜（MuJoCo 给出的就是这样）。SAP 新旧两版都给成竖直向上，等于把孔沿当成一个平台：只托住管子，不产生对中的横向力。
- 根本原因见下一节：SAP 加载网格时把管子的锥形尖端整段丢掉了。（这里最初猜测是 MPR 法向偏差，已被单对测试否定。）

## 根本原因：SAP 加载凸网格时截断凸包，管子的锥形尖端被整段丢掉

**单对测试 1：孔沿**（`tubes_pairtest.py`，只做碰撞检测，不做动力学）。管子竖直放置，轴线偏离孔心 6 mm，在锥面刚碰到孔沿的位置附近逐步下压，比较各引擎给出的最近接触：
- MuJoCo：锥面压在孔沿上，穿入 0.1 → 1.9 mm，法向倾斜（竖直分量 0.50，指向孔心 0.85），接近解析值 0.66 / 0.75。
- SAP 旧版、新版：看不到锥面与孔沿的接触。最近的接触是"管子底边在顶板上方 5.7 mm"，法向竖直，并且随下压 1:1 减小。

**单对测试 2：桌面**（`pairtest/tip_test.py`）。把管子竖直立在空旷桌面上方，管尖离桌面 10 mm 到 −1 mm：
- MuJoCo：管尖接触时距离为 0，距离从管尖量起。
- SAP 旧版、新版：在每个高度上，距离都比管尖实际高度多 **15.88 mm**，正好是锥尖的长度（15.9 mm）。说明 SAP 里的管子是一个平底圆柱，没有锥尖。

**为什么丢掉了锥尖**（`sap_warp/loader/scene.py` 中加载内联网格的路径，旧版 5208 行，新版 5182 行）：
- 凸网格顶点超过 `SapMesh.MAX_HULL_VERTICES = 64` 时，SAP 调用 `_sap_remesh_convex_hull`，用 qhull 选项 `Qt TA60` 重算凸包。
- `TA60` 的含义是"加入 60 个顶点后停止"。它得到的是一个没算完的凸包，而不是均匀简化后的形状。
- 我们的管身凸块有 218 个顶点。用同样的选项复算，得到的凸包最低点在真实管尖上方 15.88 mm，与测试 2 的数值一致。整段锥尖被切掉。
- 管盖凸块有 299 个顶点，同样被截断，但它不影响插入。
- 新旧两版都是这段代码，所以两版表现一致。MuJoCo 4.0 默认不限凸包顶点数（`maxhullvert=-1`），保留了完整形状。

**这样就解释了整个失败链：**
1. 在 SAP 里，管子是平底圆柱，半径 14 mm，孔半径 15 mm。
2. 下降时只要偏心超过约 1 mm，平底的边缘就落在顶板上。接触只能是面对面的竖直接触，没有锥面把管子导向孔心，横向力约为 0（与动态探针测到的一致）。
3. 竖直力超过手指摩擦上限，管子在手里往上滑，横向不动。
4. 松手后，管子偏心立在孔沿上，0.3 s 内倒下。
5. 调接触刚度、静摩擦容差都改变不了几何形状，所以 5 轮都无效。第 5 轮把检测距离改小，只是改变了漏碰撞的情况，同样没有解决问题。
6. MuJoCo 的管子有锥尖：锥面碰到孔沿时产生 2.3 N 指向孔心的力，管子在手里横滑对中，然后插到底。

**和之前原子能力实验的关系：** 和 round socket 孔口支撑问题（`exp-report/sap-rim-contact-root-cause*.md`）一样，都是 SAP 碰撞层的几何表示出错，而不是 SAP 求解器（接触优化）出错。机制不同：
- 那次是接触点去重容差过大、MPR 距离偏差，导致漏掉孔口的接触点。
- 这次更早一步：加载网格时形状本身就不完整。

两者的共同点是：在间隙小、靠细节几何引导的接触里，SAP 的碰撞表示会悄悄丢失关键几何，而且不报错、不警告。

**结论的性质：** 这是引擎的默认行为，不是我们的实现错误。两个引擎拿到的是同一份网格文件，SAP 在加载时把它截断了。按约定我们不修改引擎，结果照实报告。如果要做"形状一致"的补充对照，只需把凸块预先切成每块 ≤64 个顶点，不需要改 SAP 代码。本任务到此停止。

**提醒：** 其他 SAP 任务里，凡是凸块超过 64 个顶点的，都可能存在同样的形状丢失，建议逐个核查（例如 RH20T 盘子上架、叠碗中使用的网格）。
