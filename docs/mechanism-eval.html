Audited B=5 results:
three-box static friction

A bounded-tuning comparison of SAP Warp and MuJoCo on the retain-versus-eject boundary of a three-box contact stack.

Primary task
Three-box push
Budget
B=1 plus four native candidates
Local repeats
R=20 per condition
Reading rule. B=5 measures bounded engineering usability: whether a declared native configuration can recover the preregistered task boundary. It is not, by itself, a ranking of raw friction-law fidelity.

1. What this page reports

This page replaces the previous mechanism-aware claims with an audited task report. It reports only completed, comparable Three-box artifacts: a literal-default B=1 baseline and a frozen B=5 configuration for each engine. Each primary condition has 20 small initial-state perturbations.

Main result. In the shared 14-condition primary force grid, B=5 reaches 92.9% expected-outcome agreement for SAP Warp and 100% for both MuJoCo CPU and MuJoCo Warp. The remaining SAP error is the near-threshold top-box 4-N retain condition. MuJoCo's B=5 result uses its native NoSlip=2 capability; it must be interpreted as task usability, not as a raw-contact-only friction result.

2. Task setup and the four result views

Three 1-kg boxes are vertically stacked. A horizontal force pushes either the middle box or the top box. The task is classified at the end of each rollout: sub-threshold loads must retain the pushed box, while super-threshold loads must eject it.

  • Middle-box theoretical breakaway: 9.81 N; tested at 2, 4, 6, 8, 11, 13, 15, and 18 N.
  • Top-box theoretical breakaway: 4.905 N; tested at 1, 2, 3, 4, 6, and 8 N.
  • Primary optimization metric: expected-outcome agreement. Supporting diagnostics: false-positive rate, tail creep, contact duty, contact-capacity truncation, and—where exported—normal-load health and friction utilization.

3. B=5 is the primary result

The task treats eject as the positive class. The primary grid has 120 expected-eject and 160 expected-retain rollouts per engine. These are the task-level numbers used for the headline.

The task-level improvement is driven by reducing false positives: all engines still eject all intended-eject primary conditions. B=1 fails because it turns many intended retain cases into unwanted slips.

4. Which native controls materially changed the result?

The entries below record the frozen controls that improve this task; they do not assert that parameters have the same physical meaning across engines.

SAP Warp

B=5 winner: shape ke=1e5 N/m, tau=3 ms.

Observed change: primary agreement rises from 42.9% to 92.9%; all runs remain finite, continuous-contact, and untruncated.

Remaining limitation: top-box 4 N falsely slips in all 20 repeats.

MuJoCo CPU

B=5 winner: impratio=100, solreffriction_tc=0, noslip=2.

Observed change: calibration tail creep falls from 74,296 to 0.702 µm/s; primary agreement reaches 100%.

Interpretation: NoSlip is an explicit native friction correction.

MuJoCo Warp

B=5 winner: impratio=10, solreffriction_tc=4 ms, noslip=2.

Observed change: calibration tail creep falls from 89,210 to 0.717 µm/s; primary agreement reaches 100%.

Interpretation: the same NoSlip qualification applies.

Supporting diagnostics agree with the task labels where they are exported. MuJoCo B=5 retains contact duty 1.0 in primary retain cases, has no capacity overflow, and reaches friction utilization from about 0.20 to 0.83 as load approaches breakaway. SAP's public artifact confirms finite runs, contact duty 1.0, and zero truncation; it does not export a directly comparable per-condition normal-force/CV or friction-utilization summary, so this page makes no cross-engine force-health ranking.

5. Scope and limits

  • B=5 is the main usability measure, not a raw-friction score. MuJoCo's winning configurations use NoSlip; its result should not be paraphrased as “MuJoCo's untreated contact model is more accurate.”
  • Primary and transfer grids are different denominators. SAP's completed artifact covers the 14-condition primary force grid. MuJoCo additionally completed an expanded 22-condition grid: both CPU and Warp score 96.15% there, with a false-slip/contact-loss failure at the mu=0.7, m=1.0, retain transfer condition.
  • No real trajectory reference is present. This task tests expected physical transitions and solver/contact health, not real-world trajectory RMSE.
