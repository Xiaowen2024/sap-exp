## Common scene and pre-run checks

Reconstruct initial poses from source-only first-frame images and camera calibration, with declared supported-height assumptions. Admit or reject these fits before engine outcomes. Keep geometry, physical properties, source motion and controllers identical across engines. Source masses are used (broom 0.04 kg, pan 0.15 kg, each cube 0.03 kg). Freeze a shared Coulomb mu=0.3 on all contacts, with torsional/rolling friction zero: source metadata broom=0.45 and pan/cubes=0.3, so the per-material source combination is not ported. This is a controlled common-material reproduction, not an exact PhysX material port. Common inertia uses additive convex mass properties scaled to source mass. Source metadata cube size differs from the USD collision mesh: use measured collision mesh dimensions and report the discrepancy. Detached, physically articulated X5 grippers replace full robot arms, as in the previous studies. Tool handles and dustpan cavity must remain open in the common decomposition. Every convex piece must have <=64 vertices; never silently truncate vertices. Audit initial overlap, cavity/entrance geometry and fit overlay before dynamics.

Use MuJoCo 4.0.0 Warp versus SAP Warp + Newton Convex, one CUDA world on the same RTX 4090, serial executions, dt=1 ms, native solver implementations unchanged. Pin SAP source hashes and Warp version. Run SAP known-answer preflight for the exact runtime/source before accepting a task rollout; a preflight API failure is an adapter/setup issue, never a task failure. Save health/finite-state, contact-capacity/truncation flags and input tracking.

## B<=5, R=1 parameter selection

Each engine gets at most five native numerical-contact candidates, each one rollout, no statistical repeats. Start at native default contact parameters. Write each candidate and rationale before launching. Shared scene and input remain frozen; a reconstruction or observer fix invalidates the previous evaluation revision and must be reported separately, never disguised as an engine tuning improvement. Stop when the source-observed sweep/retention is reproduced without obvious invalid overlap or support. Otherwise select the physically valid candidate with the closest observed mechanism, retaining all failures. No held-out/generalizability or success-rate claims from one episode. Timing is the one actual execution with setup/JIT/telemetry identified, not a repeated warm benchmark.

## Evaluation (same user SOP as Stack Bowls)

1. Physical fidelity: time-aligned object centre RMSE / identifiable orientation and final-pose errors only where a reliable estimated reference with coverage/method/uncertainty is admitted. Missing reference = null. Distinguishable cube colour may support image-space measurements, reported separately from 3D error. Initial fitted poses are not independent trajectory ground truth. Do not fill invisible frames or force successful containment assumptions.
2. Simulation consistency: independent common-geometry sampled penetration bounds by physical object pair (10 ms), local thickness/crossing interpretation; pair-wise contact duty, longest loss and recontacts only in declared continuous-grasp/support phases (1 ms; force thresholds .001/.01/.1 N); object COM linear / world angular RMS in the same recorded-source final release window. Appended tail is supplementary. Normal transient broom–cube strikes are not required to be continuous contact.
3. Task outcome: report tool pickup/handoff, three cubes entering and staying in the pan, complete release, and retained contents. Video-observed outcome and strict valid success are separate. Obvious penetration or ongoing gripper support cannot count as valid success; missing validity audit => null. Compare to observed reference outcome without importing official policy reward thresholds. Single episode = binary/3-cube counts, no success rate.

Report first divergence stage and reconstruction limitations. Lower settling speed is not stronger reference fidelity. Do not invent missing contact or reference data. Deliver original/comparison videos, raw results, concise Markdown organized as experiment design and integrated conclusions; no Canvas. No IPC or Genesis extension.
